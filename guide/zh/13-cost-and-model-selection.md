## 模型对比

### 三个层级

| 特性 | Claude Opus 4 | Claude Sonnet 4 | Claude Haiku |
|---|---|---|---|
| **质量** | 最高 | 高 | 良好 |
| **速度** | 最慢 | 中等 | 最快 |
| **成本** | $$$ | $$ | $ |
| **上下文** | 200K（扩展到 1M） | 200K | 200K |
| **适用场景** | 复杂架构设计 | 日常编码 | 简单编辑 |

### 定价（每百万 token）

| 模型 | 输入 | 输出 | 缓存写入 | 缓存读取 |
|---|---|---|---|---|
| Claude Opus 4 | $15.00 | $75.00 | $18.75 | $1.50 |
| Claude Sonnet 4 | $3.00 | $15.00 | $3.75 | $0.30 |
| Claude Haiku 4.5 | $0.80 | $4.00 | $1.00 | $0.08 |

> 注意：价格随时可能调整，以 [anthropic.com/pricing](https://www.anthropic.com/pricing) 为准。

### 各模型适用场景

**Claude Opus 4** -- 架构师：
```
适用场景：
- 设计复杂系统架构
- 调试微妙的竞态条件或内存泄漏
- 编写关键的安全敏感代码
- 涉及深层依赖链的多文件重构
- 理解大型陌生代码库
- 需要扩展思考的任务（1M 上下文）

不适用：
- 简单文件编辑
- 运行 linter 或格式化工具
- 编写样板代码
```

**Claude Sonnet 4** -- 日常主力：
```
适用场景：
- 功能实现（大多数日常编码工作）
- 代码审查和 PR 描述
- 编写测试
- 重构单个模块
- 生成文档
- 有明确错误信息的 bug 修复

这是你的默认选择。从这里开始。
```

**Claude Haiku** -- 速度选手：
```
适用场景：
- Lint 和格式化修复
- 简单的查找替换模式
- 生成样板代码（接口、类型、schema）
- 快速语法问题
- 生成 commit 消息
- 单文件小改动

不适用：
- 需要理解多个文件的任务
- 需要复杂推理的场景
```

## Token 经济学

### 什么算作 Token

Claude 读取和写入的一切都消耗 token。一个 token 大约是 3-4 个英文字符或 1-2 个代码字符。

```
大致 token 数量：
- 1 行代码         ≈ 10-30 tokens
- 1 个函数（20行） ≈ 200-600 tokens
- 1 个文件（200行）≈ 2,000-6,000 tokens
- package.json     ≈ 500-2,000 tokens
- 典型的 CLAUDE.md ≈ 500-3,000 tokens
```

### 每次请求消耗的 Token

每次发送消息，Claude 都会处理：

```
┌─────────────────────────────────────────┐
│  系统提示（Claude Code 内部）            │  ~2,000-5,000 tokens
│  CLAUDE.md 内容                         │  ~500-3,000 tokens
│  对话历史                               │  每轮递增
│  工具结果（文件读取、命令输出）            │  可能很大
│  你的消息                               │  通常较小
├─────────────────────────────────────────┤
│  Claude 的回复                          │  输出 token（5 倍成本）
└─────────────────────────────────────────┘
```

**关键洞察**：输出 token 成本是输入的 5 倍。Claude 的长回复比你的长提示要贵得多。

### 对话历史增长

```
第 1 轮：  系统提示 + CLAUDE.md + 你的消息        = ~5K tokens
第 5 轮：  系统提示 + CLAUDE.md + 5 轮历史         = ~20K tokens
第 20 轮： 系统提示 + CLAUDE.md + 20 轮历史        = ~80K tokens
第 50 轮： 系统提示 + CLAUDE.md + 50 轮历史        = ~200K+ tokens
```

这就是为什么长会话变贵。每条消息都会重新发送整个对话。

### /compact 命令

`/compact` 将对话历史压缩为摘要，大幅减少 token 数量：

```
压缩前：80,000 tokens 的历史
压缩后：~5,000 token 的摘要

节省：后续每条消息节省 ~75,000 输入 token
```

**何时使用 /compact**：
- 完成一个主要任务后（开始下一个之前）
- 当你注意到响应变慢时
- 长会话中每 15-20 轮
- 切换到代码库的不同区域前

```bash
# 基本压缩
/compact

# 带焦点指令的压缩
/compact 保留关于认证模块的讨论，丢弃关于 CSS 修复的内容
```

### 上下文窗口大小

```
Claude Sonnet 4：200K tokens（约 150K 页代码）
Claude Haiku：   200K tokens
Claude Opus 4：  200K 标准，扩展思考可达 1M

1M tokens ≈ 整个中型代码库
200K tokens ≈ 足够大多数单功能开发
```

## 成本估算

### 小任务（约 5 分钟）

**示例**："修复 auth.ts 中错误消息的拼写错误"

```
输入：~8,000 tokens（系统提示 + CLAUDE.md + 文件读取 + 你的提示）
输出：~2,000 tokens（回复 + 文件编辑）

Sonnet 4 成本：
  输入：8K × $3.00/1M  = $0.024
  输出：2K × $15.00/1M = $0.030
  总计：~$0.05

Haiku 成本：
  输入：8K × $0.80/1M  = $0.006
  输出：2K × $4.00/1M  = $0.008
  总计：~$0.01
```

### 功能实现（约 1 小时）

**示例**："添加带邮箱验证的密码重置流程"

```
典型会话：~30 轮对话，多次文件读写

输入：~500,000 tokens 总计（所有轮次累计）
输出：~100,000 tokens 总计

Sonnet 4 成本：
  输入：500K × $3.00/1M  = $1.50
  输出：100K × $15.00/1M = $1.50
  总计：~$3.00

Opus 4 成本：
  输入：500K × $15.00/1M  = $7.50
  输出：100K × $75.00/1M  = $7.50
  总计：~$15.00

在第 15 轮使用 /compact：
  ~30% 节省 → Sonnet: ~$2.10，Opus: ~$10.50
```

### 完整项目冲刺（约 1 周）

**示例**："构建带认证、CRUD 和测试的 REST API"

```
~20 个会话，每个约 40 轮，大量文件操作

输入：~10,000,000 tokens 总计
输出：~2,000,000 tokens 总计

Sonnet 4 成本：
  输入：10M × $3.00/1M  = $30.00
  输出：2M × $15.00/1M  = $30.00
  总计：~$60.00

积极成本优化后：
  - 每 15 轮 /compact
  - 样板代码用 Haiku
  - 启用 Prompt 缓存
  优化后总计：~$25-35
```

## 成本节约策略

### 1. 根据任务复杂度匹配模型

```
简单编辑、格式化、lint         → Haiku      （最便宜）
功能开发、测试、重构           → Sonnet 4   （平衡）
架构设计、复杂调试             → Opus 4     （值得投入时）
```

**经验法则**：从 Sonnet 开始。只有 Sonnet 结果不满意时才升级到 Opus。机械性任务降级到 Haiku。

### 2. 保持 CLAUDE.md 精简

CLAUDE.md 的每一行都会随每个请求发送。臃肿的 CLAUDE.md 会悄悄耗尽你的预算。

```markdown
# 差：200 行 CLAUDE.md，冗长的解释
这个项目始于 2024 年 1 月，使用微服务架构，
因为我们发现单体应用变得难以维护。
团队决定迁移到...
（又 200 行背景故事）

# 好：40 行 CLAUDE.md，只有关键事实
## 技术栈
- TypeScript, Node 20, Express, PostgreSQL, Redis
- Monorepo: apps/api, apps/web, packages/shared

## 规范
- 文件名 camelCase，组件名 PascalCase
- 所有 API 路由在 apps/api/src/routes/
- 测试：*.test.ts 与源码同目录

## 命令
- npm run dev — 启动开发服务器
- npm test — 运行所有测试
```

**成本影响**：
```
200 行 CLAUDE.md ≈ 3,000 tokens × 每次请求
 40 行 CLAUDE.md ≈   600 tokens × 每次请求

30 轮会话（Sonnet）：
  臃肿：3,000 × 30 × $3/1M = $0.27 浪费
  精简：600 × 30 × $3/1M   = $0.05
  差异在数周使用中不断累积。
```

### 3. 积极使用 /compact

```bash
# 完成任务后
/compact

# 带上下文保留
/compact 保留数据库 schema 讨论，丢弃 CSS 修复相关内容

# 设置自动压缩（在设置中）
# Claude Code 会在上下文变大时建议压缩
```

### 4. 子代理模式保持新鲜上下文

GSD/Superpowers 模式为每个任务生成新的 Claude 实例：

```bash
# 每个子代理从干净的上下文开始
# 没有前面任务的累积历史
# 更小的上下文 = 每次请求更便宜

# 主代理编排：
"实现用户注册" → 子代理 1（新鲜上下文）
"添加邮箱验证" → 子代理 2（新鲜上下文）
"编写集成测试" → 子代理 3（新鲜上下文）
```

**为什么省钱**：不是让一个会话增长到 200K token 上下文，每个子代理只用 10-30K。

### 5. Prompt 缓存

Prompt 缓存存储频繁发送的内容（系统提示、CLAUDE.md），首次全价，后续 90% 折扣。

```
不使用缓存：
  每次请求发送完整 CLAUDE.md：$3.00/1M 每次

使用缓存：
  首次请求：$3.75/1M（缓存写入，25% 溢价）
  后续请求：$0.30/1M（缓存读取，90% 折扣）

盈亏平衡：仅 2 次请求后，缓存就开始省钱
```

Claude Code 默认为 API 使用启用 prompt 缓存。直接 API 调用：

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "你的长系统提示...",
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[{"role": "user", "content": "你的问题"}]
)
```

### 6. Batch API 批量处理

用于非交互式批量生成（便宜 50%）：

```python
# 创建一批请求
batch = client.batches.create(
    requests=[
        {
            "custom_id": "task-1",
            "params": {
                "model": "claude-sonnet-4-20250514",
                "max_tokens": 1024,
                "messages": [{"role": "user", "content": "为 auth.ts 生成测试"}]
            }
        },
        {
            "custom_id": "task-2",
            "params": {
                "model": "claude-sonnet-4-20250514",
                "max_tokens": 1024,
                "messages": [{"role": "user", "content": "为 user.ts 生成测试"}]
            }
        }
    ]
)

# 结果在 24 小时内可用
# 比实时 API 调用便宜 50%
```

**适用于**：为多个文件生成测试、批量文档、大规模重构计划。

### 7. 只传递相关文件

```bash
# 差：发送整个目录（可能是数千 token）
cat src/**/*.ts | claude "审查这段代码"

# 好：只发送相关内容
cat src/auth/login.ts src/auth/middleware.ts | claude "审查认证流程"

# 更好：让 Claude 按需读取文件
claude "审查 src/auth/ 中的认证流程"
# Claude 会选择性地只读取需要的文件
```

### 8. 精准提示减少对话轮次

更少的来回消息 = 更少的 token：

```bash
# 差：模糊提示导致 5 轮澄清
"改善一下"
# "你说的改善是什么意思？"
"性能"
# "哪个函数？"
"搜索函数"
# ...

# 好：一个清晰提示，一个回复
"优化 src/services/user.ts 中 searchUsers() 函数的性能。
 当前问题：存在 N+1 查询。
 请改用单个 JOIN 查询。"
```

## 计费与限额

### API 定价层级

```
按量付费：
  无最低承诺
  按实际使用量月度计费
  标准速率限制

规模层级（联系销售）：
  批量折扣
  更高速率限制
  高需求期间优先访问
```

### 速率限制

```
第 1 层（新账户）：
  Opus:   2K 输入 tokens/分，  8K 输出 tokens/分
  Sonnet: 8K 输入 tokens/分，  32K 输出 tokens/分
  Haiku: 16K 输入 tokens/分，  64K 输出 tokens/分

第 4 层（成熟账户）：
  限制显著更高
  在 console.anthropic.com 查看你的层级
```

**遇到速率限制时**：

```bash
# Claude Code 自动处理速率限制并重试
# 如果你看到 "rate limited" 消息：

# 1. 切换到更便宜的模型（限制更高）
/model claude-sonnet-4-20250514

# 2. 稍等片刻再重试
# 3. 使用 /compact 减少每次请求的 token 使用
# 4. 联系 Anthropic 提升你的层级
```

### 设置消费限额

## 总结

```
模型选择：
  Haiku  = 速度 + 低成本（简单任务）
  Sonnet = 平衡        （日常主力，从这里开始）
  Opus   = 质量        （复杂推理）

最大成本驱动因素：
  1. 输出 token（输入成本的 5 倍）
  2. 对话历史增长
  3. 臃肿的 CLAUDE.md
  4. 过多的来回对话轮次

最大成本节约方式：
  1. 定期 /compact
  2. 清晰、具体的提示
  3. 为任务选择合适的模型
  4. Prompt 缓存（Claude Code 自动启用）
  5. 多任务用子代理模式
```

## 组织级 Token 预算管理

个人用 Claude Code 看 `/cost` 就够了。但团队规模化使用时，需要系统性的预算管理。

### 预算分配框架

| 维度 | 做法 |
|------|------|
| **按团队分配** | 每个团队设月度 Token 预算上限，通过 API key 隔离计量 |
| **按项目分配** | 高优先级项目可用 Opus，日常维护用 Sonnet/Haiku |
| **按任务类型** | 代码生成用 Sonnet，Review/测试用 Haiku，架构设计用 Opus |
| **预留缓冲** | 保留 15-20% 预算应对突发需求（线上事故排查等） |

### 费用预测

```
月度费用 ≈ 开发者数量 × 日均 Token × 工作日 × 单价

示例：
- 10 人团队，日均 100K tokens（Sonnet）
- 月费 ≈ 10 × 100K × 22 × $3/M入 + $15/M出
- 约 $800-1500/月（取决于输入输出比）
```

### 异常消费告警

- 设置日/周消费阈值，超出时自动通知（可通过 API 用量 dashboard 或自建监控）
- 关注突然飙升——通常是死循环、过大文件输入、或 Agent 陷入重试
- 定期 Review 团队 Top 消费者，排查是否有更经济的使用方式

## 模型迁移策略

新模型发布时（如 Sonnet 4.6 → 下一代），不要一刀切升级。

### 灰度迁移四步法

1. **评估**：在代表性任务上对比新旧模型表现（代码质量、响应速度、成本）
2. **灰度**：先让 10-20% 开发者切换，收集反馈 1-2 周
3. **验证**：对比两组的 CI 通过率、bug 率、开发者满意度
4. **全量**：确认无退化后全员切换，保留旧模型 API key 作为回滚后备

### Prompt 兼容性检查

模型升级可能导致同样的 CLAUDE.md 产生不同结果：
- 升级前导出一批"标准任务"的 AI 输出作为基线
- 升级后用同样任务测试，对比输出差异
- 重点关注：代码风格变化、工具调用行为变化、遵循约束的能力
